GOLDEN BOMBS - CHANGE LOG
=========================

1. RECEIVED PROMPTS / REQUESTS
------------------------------
- Build a complete multiplayer Bomberman-style game called Golden Bombs.
- Rooms with five-character codes: create a room, share the code, join by code.
- Up to six players per room; host may start early with 1-6 players (solo allowed);
  a 30-second lobby countdown auto-starts the match.
- Random match duration between 30 and 60 seconds; highest coin count wins;
  tied players share the victory.
- Six fixed spawn zones (four corners plus the middle of the top and bottom edges)
  shuffled among players each round, with a check that no spawn is inside a block
  or trapped by indestructible walls.
- Coins scattered over the map; walking over them increases the score.
- Bombs destroy destructible walls and hurt players.
- Taking damage drops three coins (or all remaining coins if fewer) and grants
  one second of invulnerability.
- Border walls and fixed pillar walls are indestructible.
- Colorful pixel-art graphics, animations, pixel font, vibrant UI.
- Create changes.txt documenting prompts, stack, files, gameplay/graphics changes,
  run instructions, verification, and limitations.
- Later request: raise the lobby limit to 6, place players in the four corners and
  the top/bottom middle positions, and validate that spawns are not inside blocks
  or squeezed between unbreakable walls.
- Final instruction: "implement everything" / "keep implementing until it's done".

2. FRAMEWORK / STACK
--------------------
- Node.js + Express + Socket.IO authoritative game server (ES modules).
- Vite + Phaser 4 client (ES modules).
- 15x11 tile board rendered at 48px per tile from 16x16 procedural textures.
- Silkscreen pixel font bundled locally (regular + bold, OFL license).
- Server sends 20 Hz state snapshots; client interpolates positions and plays
  event-driven cosmetic effects.
- No external sprite/image assets: all art is generated from pixel matrices.

4. GAMEPLAY CHANGES / IMPLEMENTED FEATURES
------------------------------------------
- Room codes: five characters from an unambiguous alphabet, unique per active room;
  codes are normalized to uppercase, invalid/unknown/full/in-progress joins are rejected.
- Lobby: live 30-second countdown and progress bar, player list with HOST/YOU badges,
  copy-code button, host-only start button, leave button.
- Match start: server-generated map and spawn points sent to every client; round banner
  shows the random duration.
- Rooms accept up to six players; purple and red were added as the fifth and sixth
  player colors so every member is visually distinct.
- Spawns use six fixed tiles: four inner corners and the middle of the top and bottom
  edges, shuffled each round. generateMap() opens connecting lanes and
  validateSpawnTiles() rejects tiles that are blocked or have fewer than two exits
  that are not indestructible stone; Game rechecks the assigned spawns before play.
- Board: border and evenly spaced pillars are stone (indestructible); interior floor
  tiles can contain breakable brick walls.
- Coins: 12 initial coins, respawn every 2.5 seconds up to 18; pickups award one coin
  each and emit a floating "+N" indicator for the local player.
- Movement: tile-based, server-validated, 130 ms cooldown, four directions, held-key
  repeat, touch D-pad; client interpolates between snapshots.
- Bombs: one active bomb per player, 2.2 s fuse, blast range 2, 450 ms flames,
  chain reactions; owners can step off their bomb but cannot walk back onto it.
- Damage: three coins dropped (or fewer if the player has less), one second of
  invulnerability with blinking sprite, red screen flash, camera shake, particles.
- Disconnects: drop the player's coins, remove their bombs, transfer host to the next
  member, delete empty rooms.
- Results: sorted ranking, winner(s) with shared-victory handling, confetti, eight-second
  countdown, automatic return to a fresh lobby.
- Input: WASD/arrows to move, Space/E to place bombs; keyboard and pointer handlers
  ignore text inputs and modifier keys.

8. LIMITATIONS / KNOWN NOTES
-----------------------------
- Rooms and matches live only in server memory; a server restart clears them.
- No persistent accounts, matchmaking, spectator mode, or reconnect-to-room support;
  losing the connection returns the player to the menu.
- Vite prints a large-chunk warning for the bundled Phaser engine; this does not
  affect functionality.
- The client uses WebGL/Canvas via Phaser; very old browsers without modern canvas
  support are not supported.
- The bundled Silkscreen font is licensed under the SIL Open Font License (see
  client/src/assets/fonts/OFL.txt).
